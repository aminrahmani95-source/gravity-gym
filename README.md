# پلتفرم جامع عضویت چندباشگاهی | Iranian Multi-Gym Platform

> **معماری سیستم**: Modular Monolith (Clean Architecture)  
> **فناوری‌ها**: Next.js 16.3, React 19.3, Tailwind CSS 4.3, NestJS 11/12, PostgreSQL 18, Redis 8  
> **محیط هدف**: بازار ورزش و تناسب اندام ایران (RTL فارسی، درگاه شاپرک، سانس‌های جنسیتی)

## ۱. اصول پیاده‌سازی و ساختار اقتصادی

پلتفرم بر پایه اصل **تفکیک کامل اعتبار کاربر از تسویه نقدی باشگاه** طراحی شده است:
1. **قیمت اشتراک کاربر ($P_{\text{sub}}$)**: کاربر هزینه ریالی/تومانی اشتراک ۳۰ روزه را پرداخت کرده و سهمیه اعتبار ماهانه ($C_{\text{issued}}$) دریافت می‌کند.
2. **هزینه اعتباری باشگاه ($C_{\text{club}}$)**: تعداد اعتباری که برای هر بار ورود از کیف‌پول کاربر کسر می‌گردد (متناسب با سطح کیفی، سانس اوج و امکانات).
3. **تسویه نقدی باشگاه ($M_{\text{club}}$)**: بدهی مالی تعهد شده به تومان به ازای هر ورود تایید شده، مبتنی بر قرارداد B2B مستقل.
4. **نامساوی طلایی پایداری اقتصادی (Golden Bounding Inequality)**:
   $$\forall \text{ Club } i, \quad \lambda(i) = \frac{M_{\text{club}}(i) + VC_{\text{checkin}}}{C_{\text{club}}(i)} \le \lambda_{\text{max}} = \frac{P_{\text{sub}} - VC_{\text{sub}}}{C_{\text{issued}}}$$
   سیستم به صورت خودکار مانع از ثبت تعرفه‌هایی می‌شود که باعث زیان پلتفرم در مصرف ۱۰۰٪ اعضا شوند.
5. **سیاست انتقال جزئی اعتبار (۱۰٪ سقف پیش‌فرض)**: اعتبارات مصرف‌نشده به صورت کامل از بین نمی‌روند؛ تا سقف ۱۰٪ سهمیه ماهانه به دوره بعد منتقل شده و مابقی به عنوان رویداد عملیاتی انقضای اعتبار (Breakage) در زیردفتر ثبت می‌گردد.
6. **پایپ‌لاین اعتبارسنجی ۸ مرحله‌ای سرور**: بارکد پویای ۴۵ ثانیه‌ای عضو در کانتر پذیرش اسکن شده و کنترل‌های قفل توزیع‌شده ردیس، آنتی‌ریپلی نانس، اعتبار امضای رمزنگاری، تطابق سانس جنسیتی (بانوان/آقایان)، سقف ورود ماهانه و کول‌داون بررسی می‌شود.
7. **رعایت حریم خصوصی در کانتر پذیرش**: کد ملی و شماره تلفن کاربر به منظور حفظ حریم خصوصی در صفحه مانیتور پذیرش پنهان است.

## ۲. ساختار مخزن (Monorepo Directory Structure)

```
gym-app/
├── package.json                 # پیکربندی ورک‌اسپیس روت (npm workspaces)
├── docker-compose.yml           # داکر کانتینرهای PostgreSQL 18 و Redis 8
├── .env.example                 # تمپلیت متغیرهای محیطی با پارامترهای اقتصادی
│
├── infra/
│   └── init-db/
│       ├── 01-init.sql          # DDL دیتابیس پستگرس با ۱۵ جدول اصلی
│       └── 02-seed.sql          # داده‌های اولیه سطوح، باشگاه‌ها، پلن‌ها و قوانین
│
├── packages/
│   └── shared-types/            # انواع داده و مدل‌های مشترک TypeScript
│       ├── src/

│       │   ├── user.types.ts    # مدل‌های کاربر و احراز هویت

│       │   ├── ledger.types.ts  # مدل‌های لجر ضمیمه‌شونده (Append-Only) با زیردفاتر مستقل اعتباری و تسویه
│       │   ├── checkin.types.ts # توکن پویای QR و نتیجه مانیتور پذیرش
│       │   └── economics.types.ts # مدل‌های اعتبارسنجی نامساوی طلایی

└── apps/
    ├── api/                     # بک‌اند مدولار مونولیت NestJS
    │   └── src/
    │       ├── common/          # دیتابیس دوگانه (پستگرس/درون‌حافظه)، ردیس، گاردها
    │       └── modules/
    │           ├── auth/        # OTP پیامکی الگو و صدور توکن JWT
    │           ├── users/       # پروفایل کاربر و استعلام مانده اعتبار
    │           ├── gyms/        # کاتالوگ، جستجوی هاورسین، سانس و امکانات

    │           ├── ledger/      # دفترکل دوطرفه، انتقال اعتبار (Rollover) و استرداد
    │           ├── economics/   # موتور نامساوی طلایی و امتیازدهی عینی سطوح
    │           ├── checkin/     # پایپ‌لاین ۸ مرحله‌ای اعتبارسنجی بارکد پویا
    │           ├── payments/    # انتزاع پرداخت شاپرک با مرزبندی صریح ریال/تومان
    │           ├── settlements/ # دسته‌های تسویه پایا و اعتبارسنجی شماره شبا
    │           └── admin/       # پایش زنده اقتصاد پلتفرم و گزارشات
    │
    └── web/                     # فرانت‌اند مدرن Next.js 16 (App Router) و راست‌چین فارسی
        └── src/
            ├── app/
            │   ├── page.tsx     # صفحه کشف باشگاه‌ها، فیلترها و دریافت بارکد
            │   ├── plans/       # خرید و فعالسازی اشتراک‌های عضویت
            │   ├── reception/   # اسکنر و مانیتور حریم‌خصوصی کانتر پذیرش
            │   └── admin/       # داشبورد مدیریت و آزمون زنده نامساوی طلایی
            └── components/      # نوبار نقش‌ها، مودال بارکد گردشی ۴۵ ثانیه‌ای
```

## ۳. خلاصه جداول پایگاه داده (PostgreSQL Schema)

1. `users`: اطلاعات پایه کاربر، کد ملی، جنسیت، نقش و وضعیت حساب.
2. `gyms`: باشگاه‌های عضو شبکه، موقعیت جغرافیایی، شعاع ژئوفنس، شبا و وضعیت.
3. `gym_branches`: شعبات زیرمجموعه باشگاه‌ها.
4. `facilities` & `gym_facilities`: امکانات ورزشی (استخر، سونا، کراس‌فیت).
5. `gym_sans`: شیفت‌های سانس اختصاصی بانوان و آقایان با قابلیت علامت‌گذاری سانس اوج.
6. `plans`: پلن‌های قابل تنظیم پلتفرم (قیمت تومانی، سهمیه اعتبار، درصد مجاز رول‌اور).
7. `subscriptions`: اشتراک‌های فعال ۳۰ روزه کاربران.
8. `credit_ledger`: دفترکل ضمیمه‌شونده (Append-Only) رخدادهای اعتباری کاربر.
9. `gym_pricing_overrides`: هزینه اعتباری و مبلغ تسویه نقدی به تفکیک باشگاه.
10. `checkins`: لاگ تفصیلی ورود اعضا، اعتبارات کسر شده و وضعیت پذیرش.
11. `gym_payable_ledger`: بدهی‌های تومانی تعهد شده به باشگاه‌ها.
12. `settlement_batches`: دسته‌های پرداخت پایا بانکی.
13. `system_configs`: پارامترهای اقتصادی سراسری بدون نیاز به تغییر کد.
14. `audit_logs` & `fraud_events`: رخدادهای امنیتی و تغییرات قوانین.

## ۵. تست‌های خودکار ایجاد شده (Test Suite)

مجموعه تست‌های خودکار با ابزار `Vitest` با اجرای ۱۶ تست سبز تایید شدند:
* **تست‌های دفترکل (Ledger)**:
  * اثبات پایداری رابطه بنیادی $\sum \Delta \equiv \text{Balance}$ در تمام تراکنش‌ها.
  * جلوگیری ۱۰۰٪ از منفی شدن مانده اعتبار (Zero-Overdraft Protection).
  * اجرای دقیق الگوریتم انتقال ۱۰٪ اعتبار و انقضای باقیمانده به مارجین پلتفرم.
* **تست‌های اقتصاد باشگاه و نامساوی طلایی**:
  * تایید تعرفه‌های معتبر ($M/C \le 32,000$).
  * ممانعت قاطع و پرتاب استثنای خطای فارسی در تعرفه‌های متضرر کننده ($M/C > 32,000$).
  * شبیه‌سازی سناریوی سوءاستفاده‌گر اقتصادی (Scenario D) و اثبات حفظ حاشیه سود بالای ۴۶.۸٪ در مصرف ۱۰۰٪ اعتبارات در باشگاه‌های لوکس.
* **تست‌های اعتبارسنجی ورود (Check-in)**:
  * تولید بارکد پویای با انقضای ۴۵ ثانیه‌ای.
  * دفع حملات Replay Attack و اسکن مجدد بارکد تکراری.
  * اعمال کول‌داون ۲ ساعته در همان مجموعه.
  * تطابق سانس جنسیتی.
  * بررسی رعایت حریم‌خصوصی و پنهان بودن کد ملی و شماره تماس در صفحه پذیرش.

## ۶. نحوه اجرای پروژه به صورت محلی (Run Locally)

### پیش‌نیازها
* `Node.js` نسخه ۲۲ یا ۲۴
* `npm` نسخه ۱۱ یا بالاتر

### گام اول: نصب وابستگی‌ها و کامپایل تایپ‌ها
```bash
# در ریشه پروژه
npm install
npm run build -w @gym-app/shared-types
```

### گام دوم: اجرای تست‌های خودکار
```bash
npm run test
```
*(تمامی ۱۶ تست بدون نیاز به داکر و با موتور درون‌حافظه‌ای استاندارد اجرا خواهند شد).*

### گام سوم: اجرای سرور بک‌اند (API)
```bash
npm run start:dev -w @gym-app/api
```
سرور در آدرس `http://localhost:4000/api/v1` فعال خواهد شد.

### گام چهارم: اجرای وب‌اپلیکیشن کاربر و پورتال‌ها (Next.js)
در ترمینال مجزا:
```bash
npm run dev -w @gym-app/web
```
وب‌سایت در آدرس `http://localhost:3000` در دسترس است.
